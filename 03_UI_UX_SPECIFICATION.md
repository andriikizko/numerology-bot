## 2. USER FLOWS

### 2.1 Flow 1: Регістрація Нового Користувача

```
Start
  ↓
[/start] Bot надсилає привіт
  ↓
User: Вводить дату ДД.ММ.РРРР
  ↓
Bot: Валідує дату
  ├─ ❌ Помилка? → "Спробуйте ще раз (ДД.ММ.РРРР)"
  └─ ✅ OK
  ↓
Bot: Розраховує число → Ім'я
  ↓
Bot: Зберігає в БД (trial 7 днів)
  ↓
Bot: Показує Головне Меню
  ├─ 📅 Сьогодні
  ├─ 📊 Персональний Розрахунок
  ├─ ✨ Пропозиції
  └─ 👤 Профіль
```

### 2.2 Flow 2: Перегляд Щоденного Гороскопу

```
Start: User в меню
  ↓
User: Натискає "📅 Сьогодні"
  ↓
Bot: Отримує path_number користувача
  ↓
Bot: Генерує гороскоп на день
  ↓
Bot: Форматує текст (емодзі, дата)
  ↓
Bot: Відправляє повідомлення
  ↓
User: Бачить гороскоп
  ↓
User: Натискає "⬅️ Назад" (опція)
  ↓
Back to Menu
```

### 2.3 Flow 3: Покупка Персонального Розрахунку

```
Start: User в меню
  ↓
User: Натискає "📊 Персональний Розрахунок"
  ↓
Bot: Перевіряє: вже куплено?
  ├─ ✅ Так → "Ви вже маєте доступ"
  └─ ❌ Ні
  ↓
Bot: Показує опис + ціну (249 грн)
  ├─ Детальний аналіз вашого числа
  ├─ Рекомендації на кожен день
  ├─ 30 днів гороскопу в подарунок
  ↓
Bot: Кнопка "💳 Оплатити 249 грн" → LiqPay URL
  ↓
User: Натискає кнопку
  ↓
LiqPay: Перенаправляє на сторінку оплати
  ↓
User: Вводить дані карти
  ↓
LiqPay: Обробляє платіж
  ├─ ✅ Успіх
  │   ↓
  │   LiqPay: Webhook → наш сервер
  │   ↓
  │   Bot: Оновляє БД (report_purchased = true)
  │   ↓
  │   Bot: Активує гороскоп на 30 днів
  │   ↓
  │   Bot: Відправляє звіт (текст/PDF)
  │   ↓
  │   Bot: "✅ Платіж успішний! Ваш звіт готовий"
  │
  └─ ❌ Помилка
      ↓
      LiqPay: Показує помилку користувачу
      ↓
      User: Може повторити платіж
```

### 2.4 Flow 4: Активація Гороскопу (Передплата)

```
Start: User в меню
  ↓
User: Натискає "✨ Пропозиції"
  ↓
Bot: Перевіряє статус користувача
  ├─ Купив розрахунок? → Ціна 30 грн
  └─ Не купив? → Ціна 50 грн
  ↓
Bot: Показує опис гороскопу
  ├─ Щоденні персональні гороскопи
  ├─ Отримуєте о 08:00
  ├─ Автоматична передплата
  ↓
Bot: Кнопка "📅 Купити гороскоп (30/50 грн)"
  ↓
[Аналогічно Flow 3, але для гороскопу]
  ↓
Webhook: Активує horoscope_paid_until = now + 1 month
  ↓
Bot: "✅ Гороскоп активований! Завтра о 08:00 отримаєте перший"
```

### 2.5 Flow 5: Перегляд Профілю & Підтримка

```
Start: User в меню
  ↓
User: Натискає "👤 Профіль"
  ↓
Bot: Отримує дані користувача з БД
  ↓
Bot: Форматує інформацію:
  ├─ 🌟 Нумерологічне Ім'я: Філософ
  ├─ 📅 Число долі: 7
  ├─ 🎂 Дата народження: 15.03.1990
  ├─ 📊 Статус Розрахунку: ✅ Придбаний
  ├─ 📅 Статус Гороскопу: ✅ Активна (20 днів залишилось)
  ↓
Bot: Показує кнопки:
  ├─ 💬 Написати підтримці
  └─ ⬅️ Назад
  ↓
User: Натискає "💬 Написати підтримці"
  ↓
Bot: Відправляє посилання на support
  ├─ "Напишіть нам: @numerology_support"
  ├─ "Чітко вказуйте ваше Нумерологічне Ім'я"
  ↓
Bot: Логує запит в admin panel
  ├─ User ID
  ├─ User name
  ├─ Num name
  ├─ Timestamp
```

## 9. MIGRATION PATH to iOS/Android

### Незалежність від Telegram

```
Всі компоненти (логіка, дизайн, flows) розроблені 
так, щоб легко перенести на нативні платформи:

1. Bot logic → API (Node.js → Express/NestJS)
2. Telegram UI → Native UI (React Native / Flutter)
3. Firebase → Залишиться та ж
4. Admin Panel → Залишиться та ж Web
```

### API для нативних додатків (Phase 2)

```
POST /api/v1/auth/register
  Input: birth_date (YYYY-MM-DD)
  Output: { tg_id, path_number, num_name, token }

GET /api/v1/horoscope/today
  Output: { date, horoscope, path_number }

POST /api/v1/payment/create
  Input: { type: "report" | "horoscope", amount }
  Output: { liqpay_url, order_id }

GET /api/v1/profile
  Output: { user_data, subscription_status }
```
